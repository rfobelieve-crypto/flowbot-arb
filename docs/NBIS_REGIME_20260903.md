# NBIS 的溢價在 09-03 階躍了 15 bps（2026-09-05 量到）

> 起因：shadow 首跑時看到溢價 +24 bps，而設定檔的帶是 `midline 0 ± 4`。
> 回頭用 `tools/analyze.py` 與錄價器自己的分鐘資料查證，發現的不是「參數沒調」，
> 是**標的的行為換了一個 regime**。
>
> 資料：`engine/logs/NBIS/minutes.csv`，4522 分鐘 / 76.1 小時。
> 費率用今天實測的 4.5 bps（HL `userFees`）。

---

## 一、它不是漂移，是階躍

每 6 小時一桶，溢價中位（Entropy 相對 lighter）：

| 09-01 21:07 | 360 | **−5.29** | −4.53 | **+6.56** |

中間那一桶（09-03 03:07，+0.49）就是轉換。這是階躍，不是隨機遊走。

## 二、可成交的方向整個反轉了

看上表右邊兩欄——**這比溢價本身更重要**：

- **09-03 之前**：`buy_edge` 中位 +6.4…+8.3（可成交），`sell_edge` 全是負的。
  也就是說：**只買得了 Entropy，賣不掉。**
- **09-03 之後**：`sell_edge` 中位 +8.7…+14.7（可成交），`buy_edge` 全是負的。
  **只賣得了 Entropy，買不到。**

套利要靠**兩個方向都會出現**才能一來一回。這 76 小時裡，每一段都只有一個方向
可成交——只是換了邊。

## 三、它沒過這個專案自己的判準

前後兩半：

```
前半 n=2261  溢價中位 −5.07 bps  平均 −5.01  標準差 3.28
後半 n=2261  溢價中位 +9.16 bps  平均 +10.00  標準差 9.56
```

判決程式的閘門是「**前後兩半都成立**」（SNDK 判決文的原話）。這裡兩半不只是
不一致，是**符號相反**。NBIS 的 7 天閘門 **09-06 到期**，而 interim 記錄
（`results/arb_premium_verdict.json`）目前**沒有前後兩半這一欄**——所以這件事
到過閘那天才會被程式抓到。**這份文件是那個結論的預告。**

## 四、資金費跟溢價是一起動的（這解釋了階躍）

`fund_diff = hedge − entropy`，中位數：

```
全段      −2.00 bps/8h   → 做空 Entropy 每天賺 6.0 bps（年化 21.9%）
前半      −0.36 bps/8h   → 幾乎沒有
後半      −7.40 bps/8h   → 每天 22 bps（年化 81%）
```

**這不是巧合，是永續合約的機制在運作**：Entropy 出現持續溢價 → 多方付資金費 →
資金費把空方叫進來把溢價壓回去。溢價與資金費同時階躍，方向一致。

所以現在的局面是：**可成交的方向（賣 Entropy）同時也是收資金費的方向。**
價格收斂與持有成本這一次站在同一邊。

> **但不要把它讀成「持有收租」。** `NEXT_SESSION` §D 凍結過：不做持有收租的
> 前瞻時鐘（§1.07 消融證明驅動的是出場目標，不是 carry）。這裡資金費不是論點，
> 是**價格收斂論點本來就想持有的那個部位順便帶的順風**。差別在於：
> 論點失效時要出場，不能因為還在收租就抱著。

## 五、對設定的具體影響

`config_NBIS.yaml` 現在是 `midline 0 / upper 4 / lower 4`。

| 用哪段資料 | analyze.py 的建議 |
|---|---|
| 全部 76h（含階躍） | `midline −0.2 / upper 11 / lower 5` |
| 最近 24h | `midline +10.3 / upper 4 / lower 2.5` |
| 最近 6h | `midline +9.5 / upper 5 / lower 6` |

**三個都不該直接抄：**

- **76h 那組把兩個 regime 平均掉了。** `midline −0.2` 對哪一段都不對，
  而 `upper 11 / lower 5` 的不對稱只是在補償那個被平均掉的階躍。
- **24h／6h 那組只描述當前 regime。** 抄它等於押注階躍不會再發生一次——
  而我們只觀察到一次階躍，n=1，沒有任何依據說它多久發生一次。

**現況（`midline 0 ± 4`）的實際行為**：階躍前會一路買 Entropy 直到吃滿上限，
階躍後會一路賣。每一段都是單邊堆倉，不是一來一回。這正是 README 說的
「**midline 填錯是會虧錢的**」那個形狀——差別只在這次它是被 regime 換掉的，
不是一開始就填錯。

## 六、$50 尺度下這是量測風險，不是金錢風險

15 bps 的階躍打在 `max_position_usd: 40` 的滿倉上是 **$0.06**。
在 $500–1000 的賺錢尺寸上是 $0.75–1.50，仍然不大。

**真正的成本不是階躍本身，是單邊堆倉**：吃滿上限之後就停在那裡等一個
可能要 34 小時才反過來的方向（M6 存貨漂移速度要量的就是這件事）。
資金費在當前 regime 會付你 22 bps/天，所以等待有補償——**但那是這一個
regime 的性質，不是 NBIS 的性質。**

## 七、建議（不自作主張，等使用者決定）

1. **09-06 過閘時，用前後兩半跑一次判決。** 這是既有判準，不是新發明的。
2. **在那之前不要改 `midline`。** 改成 +10 是押注 regime 不再變；維持 0 是
   押注它會回來。兩個都是押注，而資料現在只支持「它會變」這一件事。
3. **`--shadow` 繼續跑**：它現在正在累積的就是「這個 regime 下機會出現的頻率」，
   而且是用真實簿口。等 09-06 那天，會有階躍後 3 天的完整樣本。
4. **要查的一件事**：09-03 那天 io:NBIS 或 lighter NBIS 上發生了什麼
   （上市/下市/預言機更換/保證金參數變更）。階躍有原因，而知道原因才能判斷
   它會不會再來。**現在標記為「未查證」，不要編故事。**
