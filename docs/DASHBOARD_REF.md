# 儀表板設計參考（2026-09-04，使用者提供的資金費率套利 Bot 截圖）

使用者傳了三張別人產品的截圖（「资金费率套利 Bot」＋一個管理端總覽），
說「後續儀表板的設計理念可以參考」。這份文件把**值得抄的**與
**我們刻意不抄的**分開寫，免得下次做 B6 時只記得畫面好看忘了為什麼。

> 前提不變：**我們的儀表板零按鈕**。它做的是「看得見引擎在想什麼」，
> 不是「按一下就下單」。下單永遠是使用者自己在交易所做，我只讀回執。
> 順序是引擎與市場優先、儀表板擺後面（使用者 2026-09-03 原話）。

## 二、值得抄的四件事

### 1. 機會卡片把「為什麼是這個數字」印在數字旁邊

一張卡片長這樣：

```
SOL/USDC - SOL/USDT                            [高风险]
Long lighter · SOL/USDC  /  Short bitget · SOL/USDT
〔24h funding 不足以覆盖开平仓手续费〕〔跨 USDT/USDC 计价，存在稳定币汇率风险〕
                    预估年化  42.60%
                    [+ 一键创建]
净 funding │ 入场价差 │ 手续费回本 │ 日收益估算 │ 下次结算
 +0.0389%  │  0.014%  │   1.0d    │   $1.17    │ 05/19 01:00
                      │ 开平 0.120% │ 0.117%/24h │
```

**那條五格指標帶才是這個設計的價值**——一個大字「42.60%」旁邊，
立刻告訴你它是由哪幾個量組成、成本多久回得來、下一次結算是什麼時候。
這正是我們 `COST_INVENTORY.md` 的紀律該長的樣子：**引用出去的數字要能
當場被重新推導**（mistake.md 2026-09-03，$30/天 高估兩個數量級那次，
救援的就是使用者一句「這是怎麼來的」）。

### 2. 「手續費回本天數」是一個好指標，我們沒有

`手续费回本 1.0d（开平 0.120%）`＝以目前的費率差，賺回一次開平倉的
手續費要幾天。它把「成本」和「速度」壓成一個可比較的純量。

我們有 `required_band_bps`（要多寬才回本）但**沒有時間版本**。
`arblib/cost_model.py` 加得出來：`開平成本 bps ÷ 每日淨收益 bps`。
對持有型（資金費、basis）比帶寬更直觀。

### 3. 風險標籤要把理由寫出來，不能只有顏色

它的 `高风险`／`低风险` 旁邊一定跟著一句白話原因（「24h funding 不足以
覆盖开平仓手续费」「入场价差、手续费覆盖和年化条件通过」）。
一個沒有理由的紅點會被訓練成忽略——跟 mistake.md 2026-09-03 那條
「永遠紅的燈跟壞掉的燈一樣沒用」是同一件事。

### 4. 空狀態要說「按什麼會發生什麼」

它的空看板寫「点击'开始扫描'后再查询交易所 funding 差」——不是一個
轉圈圈。我們的版本更需要這個：**因為我們沒有按鈕，空狀態必須說清楚
「這裡什麼時候會有東西、由誰填」**（下一次每小時班車、下一次結算…）。

## 三、刻意不抄的三件事

### 1. 一鍵創建 / 編輯 / 刪除

我們零按鈕。理由不是潔癖，是 mistake.md 2026-06-07 那道疤：破壞性操作
掛在 GET 上，被 link-preview 預取帶著 `confirm=YES` 觸發，把一個真實
倉位在 DB 裡歸零、造出孤兒倉。**會改變真實交易所狀態的東西不放在
儀表板上。**

### 2. 「最佳預估年化 42.60%」當頭條 KPI

年化是**把一個瞬間的費率差乘以 1095** 得到的數字。它跟我們自己踩過的
「144 次/天」是同一族——**由定義產生、長得像發現**。真要放，旁邊必須
同時放「這個差持續了多久」與「歷史上它維持幾小時」，否則它只是把
一分鐘的雜訊放大三個數量級。

我們的頭條應該是**已實現**的量（實際錄到的帶寬中位數、實際收斂事件數），
預估年化最多當第二排的參考值。

### 3. 只放總盈利

它的管理端同時放了四個數字，而這四個放在一起講的故事跟單看一個完全不同：

| 数字 | 值 |
|---|---|
| 总盈利 | **+$2,339.94** |
| 平均收益率 | **−0.28%** |
| 盈利策略占比 | **23.3%**（17/73） |

**總額為正、平均為負、只有不到四分之一的策略賺錢**——少數贏家扛著
一堆輸家。這跟 mistake.md 2026-06-02（aggregate lift 被 1–2 個極端 fold
撐起來，per-fold mean 其實是負的）是**完全同一個形狀**，只是換成產品面板。

**所以我們的面板規則：任何總額旁邊必須有分佈**（中位數、正的佔比、
逐標的），不得只出一個加總。這一條寫進 B6 的驗收條件。

## 四、對 B6 的具體影響

做 `arb_live_*` → `/public/arb-live` → jarvis 儀表板時：

1. 版面照它的四層（標題／KPI／機會看板／清單），**但動作區換成狀態區**。
2. 每張機會卡必須帶「怎麼算出來的」指標帶，至少：實測帶寬、要求帶寬
   （含／不含返傭兩個值）、深度上限、收斂事件數、上次收斂耗時。
3. 加「手續費回本天數」，先在 `cost_model.py` 實作再上牆。
4. 每個風險標籤都要有一句白話理由，沒有理由就不要標。
5. **任何加總數字旁邊必須有分佈**（見上）。
6. 公開面硬規則照舊（CLAUDE.md）：只出百分比、方向、時間；
   **絕不出現合約張數、美元權益、帳戶餘額、單筆部位金額**。
   截圖裡的 `$105,638.82`、`$100 投入资金` 這類欄位我們一個都不放。
